# Автоматическая обработка писем

Веб-приложение на **Django** для локальной сети: авторизация, распознавание
сканов PDF-писем в редактируемые WORD-документы и реестр обработанных сканов
с фильтрами и поиском.

## Возможности

1. **Авторизация.** Логины и пароли хранятся в SQLite (`instance/letters.db`)
   стандартной моделью пользователей Django (`django.contrib.auth`).
   Администратор создаётся автоматически при первом запуске (после миграций):
   логин `Admin`, пароль `Admin`.
2. **«Загрузка PDF-писем».** Загрузка скана письма (PDF), автоматическое
   распознавание текста (OCR, русский + английский языки, высокое разрешение
   для максимальной точности). В окне одновременно показываются исходный PDF
   и распознанный текст — текст можно редактировать. Кнопка «Сохранить WORD
   файл» открывает диалог: название файла, № входящего письма и дата
   обработки письма. Итоговый `.docx` сохраняется **на компьютер
   пользователя** (то устройство, с которого он зашёл в приложение) — в
   браузерах на основе Chrome/Edge открывается системный диалог «Сохранить
   как» с выбором папки на локальном компьютере, в остальных браузерах файл
   скачивается в папку загрузок по умолчанию.
3. **«Сканы».** Таблица всех сохранённых писем: порядковый номер, название
   письма, № входящего письма, дата сохранения, файл письма (кликабельная
   ссылка — повторно скачивает документ из служебной копии на сервере,
   на случай если понадобится найти письмо ещё раз). У каждого столбца есть
   фильтр, а также общая строка поиска — ищет совпадения по всем столбцам сразу.

## Состав репозитория

```
manage.py             — точка входа Django (запуск сервера, миграции и т.д.)
letters_project/      — настройки проекта Django
  settings.py         — пути, БД, ключ сессии, параметры OCR
  urls.py             — корневой роутинг (админка + приложение letters)
  wsgi.py             — точка входа для production WSGI-серверов
letters/              — приложение Django с бизнес-логикой
  models.py           — модель Scan (реестр «Сканы»)
  views.py            — авторизация, загрузка/распознавание PDF, сохранение
  urls.py             — маршруты приложения
  ocr.py              — рендер PDF в изображения, OCR, сборка DOCX
  apps.py             — автосоздание пользователя Admin/Admin после миграций
  admin.py            — модель Scan в стандартной админке Django (/admin/)
  migrations/          — миграции схемы БД
templates/            — HTML-шаблоны (Django Template Language)
static/               — CSS и JS
storage/uploads/      — временные PDF, загруженные для распознавания
storage/archive/      — служебные копии сохранённых WORD-файлов на сервере
                        (для повторного скачивания из таблицы «Сканы»;
                        основной экземпляр файла уходит на компьютер пользователя)
instance/             — файл базы данных SQLite и секретный ключ (создаются автоматически)
requirements.txt      — список Python-зависимостей
vendor/               — уже скачанные wheel-файлы всех Python-библиотек
                        (офлайн-установка для Linux x86_64 / Python 3.11)
```

## Что нужно для запуска

### 1. Python-зависимости

Все нужные Python-библиотеки уже загружены в папку `vendor/` (для Linux
x86_64, Python 3.11) — интернет для их установки не требуется:

```bash
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install --no-index --find-links=vendor -r requirements.txt
```

Если сервер работает на другой ОС/архитектуре (например, Windows или
Python другой версии), скачайте колёса заново на машине с интернетом:

```bash
pip download -r requirements.txt -d vendor
```

и перенесите папку `vendor/` на целевой сервер, либо просто установите
пакеты напрямую (если интернет на сервере есть):

```bash
pip install -r requirements.txt
```

### 2. Системные зависимости (не Python-пакеты)

Распознавание текста выполняется через **Tesseract OCR** — его нужно
установить отдельно, средствами операционной системы (это не Python-библиотека
и не может быть просто "скачана в репозиторий"):

- **Ubuntu/Debian:**
  ```bash
  sudo apt-get update
  sudo apt-get install -y tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
  ```
- **Windows:** скачать установщик с
  https://github.com/UB-Mannheim/tesseract/wiki, при установке отметить
  русский языковой пакет. После установки укажите путь к `tesseract.exe`
  через переменную окружения `TESSERACT_CMD`, например:
  ```powershell
  setx TESSERACT_CMD "C:\Program Files\Tesseract-OCR\tesseract.exe"
  ```
- **macOS:** `brew install tesseract tesseract-lang`

Библиотека для рендеринга PDF (`PyMuPDF`) уже входит в `requirements.txt`
и `vendor/` — отдельный Poppler не требуется.

### 3. Инициализация базы данных

База данных и таблицы SQLite создаются командой миграций Django. Учётная
запись администратора `Admin`/`Admin` создаётся автоматически сразу после
миграций (см. `letters/apps.py`):

```bash
source .venv/bin/activate
python manage.py migrate
```

В `instance/` появится файл `letters.db` со стандартными таблицами Django
(`auth_user` — учётные записи пользователей) и таблицей приложения:

- `letters_scan(id, title, incoming_number, saved_date, file_path,
  archive_filename, created_by_id, created_at)` — реестр сохранённых писем
  для окна «Сканы» (`file_path` — имя файла, под которым письмо сохранено
  у пользователя; `archive_filename` — имя служебной копии в `storage/archive/`).

### 4. Запуск приложения

```bash
source .venv/bin/activate
python manage.py migrate
python manage.py runserver 0.0.0.0:5000
```

Приложение поднимется на `0.0.0.0:5000`, то есть будет доступно в локальной
сети по адресу `http://<IP-адрес-сервера>:5000`. Узнать IP-адрес сервера
в локальной сети:
- Linux/macOS: `hostname -I` или `ip addr`
- Windows: `ipconfig`

Команда `runserver` — это сервер для разработки. Для полноценного
развёртывания в сети рекомендуется запускать через production WSGI-сервер,
например `waitress` (Windows) или `gunicorn` (Linux), и предварительно
собрать статику:

```bash
pip install gunicorn
python manage.py collectstatic --noinput
DJANGO_DEBUG=false gunicorn -w 2 -b 0.0.0.0:5000 letters_project.wsgi:application
```

### 5. Первый вход

Откройте `http://<IP-сервера>:5000/login/` в браузере, войдите под
`Admin` / `Admin`. Сразу после первого входа рекомендуется сменить пароль
администратора — это можно сделать в стандартной админке Django
(`http://<IP-сервера>:5000/admin/`, раздел «Users») или командой
`python manage.py changepassword Admin`.

## Настройка через переменные окружения

| Переменная          | Назначение                                                   | По умолчанию                     |
|---------------------|---------------------------------------------------------------|-----------------------------------|
| `DJANGO_SECRET_KEY` | Секретный ключ Django (подписи сессий/CSRF). Если не задан, генерируется автоматически и сохраняется в `instance/secret_key.txt` | генерируется автоматически |
| `DJANGO_DEBUG`      | Режим отладки Django (`true`/`false`). В продакшене должен быть `false` | `false`                    |
| `CSRF_TRUSTED_ORIGINS` | Список доверенных источников для CSRF через запятую (нужно, если приложение открывается по доменному имени за прокси), например `https://letters.example.local` | не задано |
| `ARCHIVE_DIR`       | Папка на сервере для служебных копий сохранённых WORD-файлов (используется только ссылкой в «Сканах», не место основного сохранения) | `storage/archive` внутри проекта |
| `OCR_LANGUAGES`     | Языки распознавания Tesseract                                 | `rus+eng`                        |
| `OCR_DPI`           | Разрешение рендеринга PDF для OCR (выше — точнее, но медленнее) | `300`                            |
| `TESSERACT_CMD`     | Путь к исполняемому файлу tesseract (нужно на Windows)         | берётся из `PATH`                |

## Как это работает изнутри

1. Пользователь загружает PDF на странице «Загрузка PDF-писем».
2. Сервер сохраняет PDF во временную папку `storage/uploads/`, рендерит
   каждую страницу в изображение с высоким разрешением (300 DPI) через
   PyMuPDF и распознаёт текст через Tesseract OCR (`rus+eng`).
3. Распознанный текст показывается рядом с превью PDF и доступен для
   правки прямо в браузере.
4. При нажатии «Сохранить WORD файл» пользователь вводит имя файла,
   № входящего письма и дату обработки. Сервер собирает `.docx` (через
   `python-docx`) из отредактированного текста и сохраняет служебную копию
   в `storage/archive/`; браузер получает эти же байты и сохраняет их
   **на компьютер пользователя** — через системный диалог «Сохранить как»
   (File System Access API в Chrome/Edge) либо обычной загрузкой файла в
   остальных браузерах.
5. Одновременно через Django ORM создаётся запись модели `Scan` — она сразу
   видна на странице «Сканы» с фильтрами по каждому столбцу и общим поиском.
   Ссылка в столбце «Файл письма» скачивает документ повторно из служебной
   копии на сервере (полезно, если пользователь потерял локальный файл).

## Известные ограничения / что можно доработать

- Разбор PDF в WORD сохраняет только текст (абзацы и разрывы страниц),
  без исходного форматирования, таблиц и изображений — для писем этого,
  как правило, достаточно, но при необходимости можно расширить `letters/ocr.py`.
- Выбор папки при сохранении на диск пользователя (диалог «Сохранить как»)
  поддерживается только в браузерах на основе Chromium (Chrome, Edge) —
  так устроен стандарт File System Access API. В Firefox и Safari файл
  просто скачивается в папку загрузок браузера без выбора папки.
- Приложение рассчитано на доверенную локальную сеть; для дополнительной
  защиты рекомендуется закрыть порт 5000 фаерволом от внешнего доступа,
  использовать HTTPS-прокси (например, nginx) и запускать с `DJANGO_DEBUG=false`.
