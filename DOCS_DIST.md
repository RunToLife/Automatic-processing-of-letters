# Гендальф — руководство по собранному приложению

Это руководство — для тех, кто **использует** уже собранное приложение
«Гендальф» (папка с `Гендальф.exe`), а не работает с исходным кодом.
Если вы разработчик и хотите пересобрать приложение или изменить код —
см. раздел [«Для разработчика»](#для-разработчика) в конце.

## 1. Структура папки сборки

После сборки (`build.bat`) результат лежит в `dist\Гендальф\`. Именно эту
папку целиком нужно передавать пользователям и запускать на их компьютерах.

```
Гендальф\
  Гендальф.exe          <- запускаемый файл, ярлык делайте на него
  README.md              <- копия этого файла (кладётся автоматически при сборке)
  _internal\              <- всё остальное, нужное приложению для работы
    vendor\tesseract\      <- портативный Tesseract OCR (tesseract.exe, DLL, tessdata, LICENSE.txt)
    static\                 <- CSS/JS (в т.ч. оформление /admin/)
    templates\              <- HTML-шаблоны
    app.ico                 <- иконка окна
    ... (Python-интерпретатор, Django и другие библиотеки)
  data\                    <- появляется при первом запуске: БД, загрузки, логи (см. раздел 3)
```

**Что можно трогать:**
- Можно переименовать/переместить всю папку `Гендальф\` целиком (например,
  на другой диск) — приложение найдёт свои файлы относительно
  `Гендальф.exe`, где бы он ни лежал, включая пути с пробелами и
  кириллицей.
- Можно (и нужно, для резервных копий) копировать папку `data\` — см.
  раздел 3.
- Можно добавлять новые файлы `.traineddata` в
  `_internal\vendor\tesseract\tessdata\` — см. раздел 6.

**Что трогать не нужно:**
- **Не переименовывайте и не удаляйте отдельные файлы внутри `_internal\`**
  — это не "мусор" и не кэш, а часть самого приложения (интерпретатор
  Python, все библиотеки, статика, шаблоны, Tesseract). Без любого из этих
  файлов приложение может перестать запускаться или работать частично.
- Не переименовывайте сам `Гендальф.exe` — под этим именем ищутся
  некоторые внутренние пути.

## 2. Запуск и остановка

**Запуск:** дважды щёлкните `Гендальф.exe`. Через несколько секунд:
- в трее/на панели задач появится небольшое окно «Гендальф» со статусом и
  адресом сервера (обычно `http://127.0.0.1:5000/`);
- автоматически откроется браузер по умолчанию на этом адресе.

Если браузер не открылся сам — откройте его вручную и введите адрес,
показанный в окне «Гендальф».

**Остановка:** в окне «Гендальф» нажмите кнопку **«Остановить и выйти»**,
либо просто закройте это окно крестиком — оба способа корректно
останавливают сервер и завершают процесс. Простое закрытие вкладки
браузера сервер **не останавливает** — само приложение живёт в окне
«Гендальф», а не в браузере.

**Если порт занят.** Приложение всегда сначала пробует открыть порт
`5000`. Если он занят другой программой, оно автоматически подбирает
следующий свободный (`5001`, `5002`, ...) — какой именно порт
использован в итоге, всегда показано в окне «Гендальф» и в файле
`data\logs\gendalf.log`. Никаких действий от вас не требуется — просто
смотрите на адрес в окне/логе, а не предполагайте, что это всегда `5000`.

**Работа в локальной сети.** Приложение привязано только к
`127.0.0.1` (localhost) — оно доступно **только с этого же компьютера**,
не с других машин в сети. Это осознанное ограничение безопасности для
десктопной сборки. Если вам действительно нужен доступ с других
компьютеров сети — это отдельная задача (запуск как сетевого сервиса, не
через этот exe-лаунчер); обратитесь к разработчику.

## 3. Где хранятся данные

Все изменяемые данные лежат в папке `data\` **рядом с `Гендальф.exe`**
(создаётся автоматически при первом запуске):

```
data\
  instance\
    letters.db          <- база данных SQLite: пользователи, реестр "Сканы"
    secret_key.txt       <- служебный ключ (не переносите отдельно от базы)
  storage\
    uploads\              <- временные PDF, которые вы загружали для распознавания
    archive\               <- служебные копии сохранённых WORD-документов
                             (нужны для работы ссылок в таблице "Сканы")
  logs\
    gendalf.log           <- журнал работы приложения (см. раздел 7)
```

Если папка `data\` рядом с exe недоступна для записи (например,
приложение установлено в `C:\Program Files\` без прав администратора),
приложение автоматически создаёт данные в
`%LOCALAPPDATA%\Гендальф\` вместо этого. Проверить, где реально лежат
данные в вашем случае, можно так: откройте `%LOCALAPPDATA%\Гендальф` в
Проводнике (`Win+R` → вставить путь) — если там есть `instance\letters.db`,
данные там; если нет — они в `data\` рядом с exe.

### Резервная копия

Просто скопируйте всю папку `data\` (или `%LOCALAPPDATA%\Гендальф`, если
данные там) куда-нибудь ещё — например, на внешний диск или в облако.
Больше ничего не нужно.

### Перенос на другой компьютер

1. Установите/скопируйте туда саму сборку `Гендальф\` (см. раздел 9).
2. Один раз запустите `Гендальф.exe` на новом компьютере и сразу
   остановите — это создаст пустую папку `data\` с нужной структурой.
3. Замените созданную пустую `data\` на скопированную с прежнего
   компьютера (папку целиком).
4. Запустите `Гендальф.exe` — все пользователи, сохранённые письма и
   документы будут на месте.

## 4. Обновление приложения

Чтобы обновить приложение до новой версии **без потери данных**:

1. Остановите текущую версию (кнопка «Остановить и выйти»).
2. Сделайте резервную копию `data\` (см. раздел 3) — на всякий случай.
3. Скачайте/получите новую сборку `Гендальф\`.
4. **Скопируйте папку `data\` из старой сборки в новую** (замените пустую
   `data\`, которая появится в новой сборке при первом запуске, либо
   скопируйте `data\` в новую папку ДО первого запуска).
5. Удалите папку старой сборки (или оставьте как резервную копию).
6. Запустите `Гендальф.exe` из новой папки.

При запуске новой версии база данных автоматически обновится до нужной
структуры (миграции применяются автоматически при каждом старте) — это
безопасно и не требует ручных действий, даже если в новой версии
изменилась схема базы данных.

## 5. Настройка

Приложение настраивается переменными окружения Windows (задаются перед
запуском `Гендальф.exe`, например через `set ПЕРЕМЕННАЯ=значение` в
командной строке, или через системные переменные среды Windows).

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `GENDALF_DEBUG` | `1` включает подробные логи (DEBUG) и открывает консольное окно поверх обычной сборки без консоли — см. раздел 7 | выключено |
| `DJANGO_SECRET_KEY` | Свой секретный ключ вместо автоматически сгенерированного в `data\instance\secret_key.txt` | генерируется автоматически |
| `ARCHIVE_DIR` | Папка для служебных копий сохранённых WORD-файлов (например, путь к сетевой шаре, если несколько копий приложения должны видеть один и тот же реестр «Сканы») | `data\storage\archive` |
| `OCR_LANGUAGES` | Языки распознавания Tesseract, через `+` | `rus+eng` |
| `OCR_DPI` | Разрешение рендеринга PDF для OCR (выше — точнее, но медленнее) | `300` |
| `TESSERACT_CMD` | Путь к другому `tesseract.exe`, если не хотите использовать встроенный в `_internal\vendor\tesseract\` | встроенный портативный Tesseract |

Нет ни `.env`-файла, ни отдельного файла настроек — все параметры именно
через переменные окружения. Если ни одна переменная не задана, приложение
работает с безопасными значениями по умолчанию, описанными выше.

## 6. Добавление языков OCR

Чтобы распознавать ещё один язык (например, украинский или казахский):

1. Найдите файл `<код_языка>.traineddata` для нужного языка — самый
   надёжный источник: официальный репозиторий Tesseract,
   https://github.com/tesseract-ocr/tessdata (или `tessdata_best`/
   `tessdata_fast` — более точные/более быстрые варианты соответственно).
   Код языка — трёхбуквенный (например, `ukr`, `kaz`, `deu`).
2. Скопируйте файл в `Гендальф\_internal\vendor\tesseract\tessdata\`.
3. Задайте переменную окружения `OCR_LANGUAGES`, включив новый язык, через
   `+`, например:
   ```
   set OCR_LANGUAGES=rus+eng+ukr
   ```
   и запустите `Гендальф.exe` из той же командной строки (или задайте
   переменную в системных переменных среды Windows, чтобы это применялось
   всегда).
4. Перезапустите приложение.

Приложение не нужно пересобирать — файлы `.traineddata` подхватываются
сразу из `tessdata\`, достаточно положить файл и перезапустить exe.

## 7. Диагностика

### Включить подробные логи и консоль

Самый быстрый способ понять, что происходит: закройте приложение, затем
в командной строке (`cmd.exe`), находясь в папке с `Гендальф.exe`,
выполните:

```
set GENDALF_DEBUG=1
Гендальф.exe
```

Откроется дополнительное консольное окно с подробным (DEBUG) логом в
реальном времени — так видно, на чём именно приложение остановилось,
без необходимости искать и читать файл лога. Тот же самый лог всегда
пишется и в файл `data\logs\gendalf.log` (даже без `GENDALF_DEBUG`) —
если приложение не запускается вовсе или падает раньше, чем успевает
показать окно, **всегда сначала смотрите в этот файл**, там останется
полная трассировка ошибки (это специально сделано, чтобы ошибки не
терялись, даже когда приложение работает без консоли).

### Частые проблемы

**Windows SmartScreen «Windows защитила ваш компьютер».**
Ожидаемо для несертифицированного (неподписанного) exe от небольшого
проекта — сама Windows не может проверить издателя. Нажмите
«Подробнее» → «Выполнить в любом случае». Если это происходит регулярно
и мешает пользователям — решение только одно, платное: подписать exe
сертификатом code signing (это отдельная тема, не входит в сборку).

**Антивирус блокирует или удаляет `Гендальф.exe`.**
PyInstaller-сборки иногда ложно детектируются некоторыми антивирусами
(особенно эвристическими) как подозрительные — это известная особенность
самого PyInstaller, а не признак реальной проблемы. Добавьте папку
`Гендальф\` в исключения антивируса. Если это критично для массового
распространения — стоит подписать exe (см. выше) и/или сообщить в
антивирусную лабораторию о ложном срабатывании (submit false positive).

**Отсутствует Microsoft Visual C++ Redistributable.**
Если при запуске Windows пишет что-то вроде «не найден
VCRUNTIME140.dll» — на компьютере нет нужной библиотеки Visual C++
Runtime (её иногда не бывает на "совсем чистых" Windows). Установите
"Microsoft Visual C++ Redistributable" (x64) с официального сайта
Microsoft и запустите приложение снова.

**Брандмауэр Windows спрашивает про доступ к сети.**
Так как сервер слушает только `127.0.0.1` (сам себя), для нормальной
работы это разрешение не требуется — можно ответить «Отмена»/«Запретить
доступ». Если Windows всё же продолжает спрашивать при каждом запуске —
это не мешает работе приложения, можно просто закрывать это окно.

**«Нет прав на запись» / приложение не может создать `data\`.**
Обычно значит, что папка `Гендальф\` лежит там, куда обычному
пользователю нельзя писать (например, прямо в `C:\Program Files\` без
прав администратора). Приложение само пробует переключиться на
`%LOCALAPPDATA%\Гендальф\` в этом случае (см. раздел 3) — но если и туда
нет доступа, посмотрите точный текст ошибки в
`data\logs\gendalf.log`/консоли отладочного режима. Самое простое решение
— переместить папку `Гендальф\` куда-нибудь, где у пользователя точно
есть права на запись (например, в `Документы` или на рабочий стол).

**Не найден Tesseract / OCR не работает.**
Проверьте, что в `Гендальф\_internal\vendor\tesseract\` действительно
лежит `tesseract.exe` и рядом с ним DLL-файлы (если папка пустая — сборка
была сделана без выполнения инструкции из `vendor\tesseract\README.md`,
это ошибка сборки, а не установки; нужна пересборка с правильно
заполненной папкой). Также проверьте `data\logs\gendalf.log` — там будет
конкретный текст ошибки от Tesseract.

**Пошаговая диагностика при любой непонятной проблеме:**
1. Включить `GENDALF_DEBUG=1` (см. выше) и посмотреть на вывод консоли.
2. Открыть `data\logs\gendalf.log` (или `%LOCALAPPDATA%\Гендальф\logs\gendalf.log`) и прочитать последние строки — там либо явная ошибка, либо трассировка Python.
3. Проверить, что `_internal\` не повреждена/не урезана антивирусом (сравнить размер папки `Гендальф\` с исходной, только что собранной/скачанной).
4. Проверить права на запись в папку, где лежит `Гендальф\` (или сразу попробовать переместить её в `Документы`).
5. Если ничего не помогло — переслать разработчику файл `data\logs\gendalf.log` целиком, это почти всегда сразу показывает причину.

## 8. Для разработчика

### Пересборка

```bat
:: из корня репозитория, на Windows
build.bat
```

`build.bat` сам создаёт чистое виртуальное окружение, ставит зависимости,
собирает статику (`collectstatic`) и вызывает `pyinstaller app.spec`.
Подробности каждого шага — прямо в комментариях `build.bat`.

Отладочная сборка (exe с консолью вместо обычной без консоли):
```bat
set GENDALF_BUILD_CONSOLE=1
build.bat
```

### Добавление нового ресурса (шаблон, статика, файл) в сборку

1. Положите файл в `templates/`, `static/` или другую папку репозитория.
2. Если это НЕ `templates/`/`static/`/`vendor/tesseract/` (уже перечислены
   в `app.spec`) — добавьте новую пару в список `datas` в `app.spec`:
   ```python
   datas = [
       ...
       ("моя_папка", "моя_папка"),  # источник в репозитории -> путь внутри _internal
   ]
   ```
3. В коде обращайтесь к этому ресурсу только через `paths.resource_path("моя_папка/файл")` — **никогда** через относительные пути или `__file__` напрямую, иначе ресурс не найдётся в собранном приложении (см. также правило про `user_data_dir()` для изменяемых данных - `paths.py` целиком описывает эту границу).
4. Пересоберите (`build.bat`).

### Добавление новой Python-зависимости

1. Добавьте её в `requirements.txt` (с точной версией — `pip freeze` после
   `pip install` покажет актуальную).
2. Установите её в любое рабочее окружение и запустите приложение из
   исходников (`python manage.py runserver`), чтобы убедиться, что она
   вообще работает.
3. Пересоберите (`build.bat`) и проверьте лог PyInstaller на новые
   `WARNING: hidden import ... not found` — если зависимость сама грузит
   что-то по строковым путям (как это делает Django), добавьте нужные
   модули в `hiddenimports` в `app.spec` (можно через
   `collect_submodules("имя_пакета")` — см. уже имеющийся пример в
   `app.spec`).
4. Запустите собранный exe и проверьте, что всё действительно работает
   (не только что PyInstaller завершился без ошибок) — отсутствие ошибки
   сборки не гарантирует отсутствия `ModuleNotFoundError` при запуске.

### Отладка frozen-режима без пересборки exe

- `GENDALF_DEBUG=1` перед запуском `Гендальф.exe` — подробные логи и
  консоль (см. раздел 7).
- Можно запускать `launcher.py` (тот же скрипт, что становится точкой
  входа exe) прямо из исходников: `python launcher.py` — это ведёт себя
  почти как frozen-сборка (те же миграции, тот же подбор порта, то же
  окно), но пути ресурсов и данных берутся из репозитория (`sys.frozen`
  ещё не установлен) — удобно для проверки логики без сборки.
- Если проблема воспроизводится только в РЕАЛЬНОЙ сборке — читайте
  `build/app/warn-app.txt` и `build/app/xref-app.html` (создаются
  PyInstaller-ом при каждой сборке) - там видно, что именно было и не
  было найдено при анализе зависимостей.

### Запуск из исходников (не менялось этим проектом упаковки)

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver 0.0.0.0:5000
```

Подробности — в `README.md` в корне репозитория.

## 9. Распространение

### Упаковка в zip

```powershell
Compress-Archive -Path "dist\Гендальф" -DestinationPath "Гендальф.zip"
```

Или через Проводник: правой кнопкой по папке `dist\Гендальф` →
«Отправить» → «Сжатая ZIP-папка». Пользователь распаковывает архив
**целиком** (не только `.exe`!) в любое удобное место и запускает
`Гендальф.exe` из распакованной папки.

### Что сказать пользователям про SmartScreen

Приложение не подписано сертификатом (это платная услуга, отдельная от
самой сборки), поэтому при первом запуске Windows Defender SmartScreen,
скорее всего, покажет предупреждение «Windows защитила ваш компьютер».
Это нормально для внутренних/некоммерческих инструментов — предупредите
пользователей заранее, что нужно нажать «Подробнее» → «Выполнить в любом
случае». Так же может повести себя антивирус (см. раздел 7).

### Лицензии

Tesseract OCR распространяется по лицензии **Apache License 2.0**.
Условия этой лицензии требуют, чтобы текст лицензии поставлялся вместе с
программой, использующей Tesseract, поэтому:

- `vendor/tesseract/README.md` явно требует положить `LICENSE.txt` в
  `vendor/tesseract/` перед сборкой;
- `app.spec` включает всё содержимое `vendor/tesseract/` (включая
  `LICENSE.txt`) в сборку через `datas`;
- в результате `LICENSE.txt` окажется в
  `Гендальф\_internal\vendor\tesseract\LICENSE.txt` в каждой сборке —
  **не удаляйте этот файл** при распространении приложения.

Сам код приложения «Гендальф» — используйте лицензию, которую вы сами
для него определите (в этом проекте лицензия отдельно не оговаривалась).
